# Architecture

An independent loopback Node server serves a static browser app, a local set catalogue, set-restricted cached CAD templates, and a persistent YOLO/MobileSAM Python worker. The selected set's requirements are the recognition scope. No sibling app is required at runtime and no user photo reaches Rebrickable.

`public/engine/` is a vendored snapshot of the established brick-finder geometry/descriptor kernel. ENGINE_BASELINE.json records source hashes. It supplies PCA-aligned silhouettes, exact-view overlap, stud grids, hollow underside tubes with conditional hidden-stud inference, CAD parsing and review rendering. Offline scripts install checksum-pinned LDraw and models; generated data is ignored.

`scripts/setup-sets.mjs` builds an offline database from Rebrickable CSVs. Latest inventory versions are selected; spare parts are omitted by default; nested set/minifigure inventories are expanded at lookup with cycle/missing-reference checks. Required exact part/colour/quantity lines are preserved. Printed parts can be mapped to base geometry, with explicit ambiguity. Explicit LDraw `Moved to` redirects are followed; undocumented aliases and absent geometry remain inventory requirements available for manual review.

The server selects cached view masks/surface metadata only for the requested mapped IDs. A browser worker builds/retains a small scoped index and performs search using the same kernel. No full-library search is performed for this app. Colours contribute conservative eligibility checks; they do not establish exact element identity. Detection/loading/comparison progress and cancellation remain visible.

`public/assignment.mjs` performs maximum-weight capacity-constrained assignment between physical photo regions and inventory lines. A region can satisfy at most one line, each line has its required quantity, and fixed user confirmations reserve capacity. Rejected/weak/nonmatching regions stay unassigned. Confirmed, likely, ambiguous and rejected have distinct overlays and counts. Manual corrections cannot overfill a line. Assignment is recomputed after corrections, not greedily locked in detection order.

The browser holds transient photo/masks/results. Photo-space masks drive overlay hit-testing and tinting, not padded crop rectangles. The review panel reuses the CPU CAD renderer, caches the matched pose and offers inspection rotation without mutating scores or confirmation. Exports contain metadata only. The local server validates Host, same-origin JSON, body limits and static-file realpaths. Model inference is serialized; cancellation terminates the owned worker.

Tests use synthetic geometry/inventories and mock inference rather than requiring model downloads or personal photos. This app is a decision aid, not calibrated vision or live AR tracking. Its restricted candidate set improves tractability but increases forced-match risk; thresholds, abstention and human review are deliberate safeguards.

Pipeline inspection captures raw and principal-component SAM masks before filters, with stable proposal IDs and explicit keep/reject reasons. These diagnostic masks use row-major runs at SAM's working resolution, capped at 400 with a visible truncation notice. The browser validates and renders them at photo scale without expanding every proposal to a full-resolution pixel array. Original/YOLO/SAM/cleanup/rejection/retained/surface-feature/set-match buttons reuse cached results and do not alter matching, filters or confirmation state. Diagnostic overlays are independent of set filtering. They remain transient and are not included in report exports.

YOLO prompts carry their confidence and SAM-space box into filtering. Masks supported by confidence ≥0.2, SAM quality ≥0.8 and ≥90% containment inside a box expanded by 10% (minimum 2 pixels per side) use minimum area max(20, image area ×0.00003), versus max(90, image area ×0.0005) for unsupported/automatic proposals. Texture similarity is a diagnostic warning rather than rejection for supported masks. Duplicate and boundary/background safeguards are unchanged; no rectangular shape constraint is imposed. This improves recall but does not split merged detections or recover pieces YOLO never proposed. The bridge replaces idle persistent workers when Python source mtimes change, and ignores late output from replaced workers. Missing legacy diagnostics get a visible UI explanation and are excluded from cache reuse.

`public/tiled-segmentation.mjs` augments the established decoder's request with a source JPEG; vendored kernels remain unchanged. The browser retains both decoded source and bounded working canvases. Source limits are 32 MP / 10,000-pixel edges / 40 MB encoded JPEG; segmentation JSON is capped at 64 MB (templates remain 8 MB). The worker independently verifies source dimensions and aspect ratio. `yolo_detector.py` scans 1536-pixel source tiles with 25% overlap plus the whole image; internal-edge-clipped proposals are discarded, then IoU-only NMS at 0.45 merges duplicate boxes without suppressing small nested boxes merely for containment. At most 200 merged proposals are processed. `tiled_pipeline.py` encodes a padded source crop per proposal for MobileSAM, applies the existing filters locally, detects surface features in source coordinates, then inverse-maps mask pixel centres and feature coordinates to the working photo. Sparse row-major runs deduplicate projected masks; no bank of full-source masks is retained. Diagnostics are in working-photo coordinates rather than the former global 1024-pixel SAM grid. The existing mask-overlap nested rejection remains; tiled detection alone does not resolve assemblies/occlusion or guarantee pins inside wheels survive filtering. Detection detail changes YOLO inference size, not source tile size. Model checkpoints are unchanged.
